# コーディング規約

このドキュメントでは、実装時の基本的なコード品質ルールを定義します。

## 1. 基本方針

- 既存の設計、命名、ディレクトリ構成に合わせる。
- 型で表現できる制約は型で表現する。
- 入力値は境界で検証する。
- 例外やエラーはユーザーと開発者が原因を追える形で扱う。
- 不要な抽象化を避け、実際に重複や複雑さを減らす場合にだけ共通化する。

## 2. TypeScript

- `any` の利用は避ける。
- APIの入力と出力はスキーマで定義する。
- ドメイン上の状態は文字列リテラル型や列挙的な型で表現する。

## 3. フロントエンド

- UI状態、サーバー状態、フォーム状態を混同しない。
- 画面上の成功、失敗、読み込み中、空状態を明示する。
- コンポーネントは責務が分かる単位で分割する。

## 4. バックエンド

- ルーティング、バリデーション、ユースケース、永続化の責務を分ける。
- 外部入力はAPI境界で検証する。
- ビルド実行やLLM連携など失敗しやすい処理は、状態とログを残す。

## 5. テスト

- 重要なドメインロジックは単体テストを用意する。
- APIは正常系と主要な異常系を確認する。
- 学習者と管理者の主要フローはE2Eテスト対象にする。
