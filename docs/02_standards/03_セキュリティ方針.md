## AI Summary

ビルド環境はアプリ本体・DB・秘密情報から分離する。学習者コード・アップロードファイル・LLM生成物は信頼しない。秘密情報をブラウザ・ビルド環境・LLM へ渡さない。LLM生成物は必ず draft 保存。外部公開時は認証・認可・レート制限・監視が必須。

## 1. 目的

Flutter学習アプリのMVPおよび将来の外部公開に向けたセキュリティ方針を定義する。ブラウザで編集したコードをサーバー側でビルドするため、ビルド環境の隔離・秘密情報の保護・Admin機能の保護・LLM生成物の管理を重要項目として扱う。

## 2. 前提

- MVP第一段階: ローカルDocker上でアプリ・DB・ビルド環境を動作させる。
- MVP第二段階: クラウド上にデプロイし、ビルド要求ごとに一時コンテナを生成する。
- MVPでは本格的な認証は必須としない。外部公開時は認証・認可・レート制限・監視を必須とする。

## 3. 基本方針

- 学習者のコードは信頼しない。
- アップロードされたファイルは信頼しない。
- LLM生成物は信頼しない。
- Admin機能は学習者向け機能と分離する。
- ビルド環境はアプリ本体・DB・秘密情報から分離する。
- 秘密情報をブラウザ・ビルド環境・LLMへ渡さない。
- 外部公開時は認証・認可・レート制限・監視を導入する。

## 4. 信頼境界

| 境界 | 方針 |
|------|------|
| Browser → Backend | API境界で入力値を検証する |
| Backend → Builder | 検証済みのプロジェクトファイルだけを渡す |
| Builder → DB | 直接接続させない |
| Builder → Host | 任意のホストファイルへアクセスさせない |
| Builder → Secret | APIキー・DB接続情報・環境変数を渡さない |
| Backend → LLM | 必要最小限の学習コンテキストだけを送る |
| Admin API | 学習者向けAPIとは別の権限境界として扱う |

## 5. ビルド環境の隔離

ビルドはアプリ本体と分離したDockerコンテナまたは一時ワークスペースで実行する。ビルド環境からホストファイル・アプリ本体・DB・秘密情報・Admin API・LLM APIキーへのアクセスを許可しない。

第一段階はローカルDockerで隔離する。第二段階はビルド要求ごとに一時コンテナを生成する。

## 6. 編集可能範囲

編集できるのはビルド用ワークスペース内のプロジェクトファイルのみ。次の操作は許可しない。

- ホストファイルへのアクセス
- アプリ本体への書き込み
- 秘密情報へのアクセス
- 任意シェルコマンドの直接実行
- ビルドワークスペース外へのファイル書き込み

## 7. アップロードファイル検証

| 項目 | MVP目安 |
|------|---------|
| 1ファイルのサイズ上限 | 1MB |
| 合計サイズ上限 | 50MB |
| ファイル数上限 | 500ファイル |
| 必須構成 | `pubspec.yaml` と `lib/` を含むFlutterプロジェクト |

`..` を含むパス・絶対パス・ビルド環境外を参照するパス・実行に不要なバイナリ・キャッシュは拒否する。

## 8. Admin機能の保護

Admin画面では教材の追加・編集・公開状態変更・一括削除・LLM生成を扱う。MVPでは本格ログイン機能を必須としない。Admin APIは学習者向けAPIとは別の権限境界として扱う。

外部公開時には次を必ず導入する: Admin認証 / Admin認可 / Admin操作ログ / CSRF対策 / レート制限 / 監査可能な変更履歴

## 9. LLM生成物の扱い

LLMが生成した教材・修正案は信頼しない。必ず `draft` として保存し、管理者が次の観点で確認してから公開する。

教材内容の正確性 / コードの実行可否 / 依存関係の妥当性 / 著作権 / 誤情報 / セキュリティ上危険なコードの有無

## 10. LLMへ送るコンテキスト情報

送ってよい情報: 教材本文・学習目標・現在のコード・ビルドログ・エラーログ・ユーザーの質問

送ってはならない情報: 秘密情報・APIキー・DB接続情報・ホストパス・個人情報・Admin用の内部情報

## 11. ビルド成果物の公開制御

成果物は推測困難な一時URLまたは認可された経路で参照できるようにする。第二段階でクラウド化する場合は、成果物ストレージ・アクセス制御・有効期限・削除方針を定義する。

## 12. 複数リクエスト処理

| 項目 | MVP目安 |
|------|---------|
| 同時ビルド数 | 1〜2ビルド |
| タイムアウト | 5分 |
| 上限超過時 | 待機、またはユーザーへ再実行を促す |

本格的なビルドキュー・複数ワーカー・優先度制御はMVP第二段階で検討する。

## 13. サプライチェーン攻撃対策

- 依存パッケージの脆弱性監査をCIまたはローカルチェックで実行する。
- パッケージの最新バージョンはリリース直後に即時採用しない（観察期間3日以上）。
- Renovateなどを使う場合は `minimumReleaseAge: 3 days` 相当を設定する。

## 14. 外部公開時に必須となる項目

ユーザー認証 / Admin認可 / CSRF対策 / レート制限 / ビルドリソース制限 / ビルドキュー / ログ監視 / アラート / 成果物の有効期限管理 / Admin操作ログ / バックアップ

## 15. 禁止事項

- 秘密情報をGitHub・ログ・ビルド成果物・LLMコンテキストに含めること
- 学習者コードをアプリ本体と同じ権限で実行すること
- LLM生成物を確認なしで公開すること
- Admin APIを学習者向けAPIと同じ権限境界で扱うこと
- アップロードファイルを検証せずに展開すること
