# ドキュメント管理規定

このドキュメントでは、docs配下の文書分類、更新方針、下書きの扱いを定義します。

## 1. 基本方針

- 正式文書と下書きを分けて管理する。
- 正式文書は実装判断の根拠として扱う。
- 下書きは未整理の検討、長文メモ、試作、調査途中の情報を置く場所として扱う。
- 実装時に参照する内容は、下書きではなく正式文書へ反映してから使う。

## 2. ディレクトリ分類

- `01_requirements/`: 何を作るか、何を満たすか。
- `02_standards/`: どのような規約や方針で作るか。
- `03_design/`: 要求をどう実現するか。
- `04_project/`: いつ、どの順序で進めるか。
- `05_references/`: 外部情報や参考リンク。
- `06_images/`: 正式文書で参照する画像。
- `99_drafts/`: 下書き、未整理メモ、試作物。

## 3. 命名規則

- フォルダ名は英語を基本とする。
- Markdownファイル名は `01_要求仕様書.md` のように番号と日本語名を組み合わせる。
- 画像ファイル名は画面番号や用途が分かる名前にする。
- 可能であれば、画像名では括弧より `_` を優先する。

## 4. AI向け要約

AIに読ませるためだけの全文複製は避ける。

AI向けに短い情報が必要な場合は、正式文書の先頭に `AI Summary` を追加するか、将来的に `ai-context/` を作成して読む順番と短い要約だけを管理する。

## 5. 更新ルール

- 要求が変わった場合は、関連する設計書と受け入れ基準も確認する。
- 設計が変わった場合は、要求仕様との矛盾がないか確認する。
- 下書きから正式文書へ反映した場合、必要に応じて下書き側に反映済みであることを残す。
