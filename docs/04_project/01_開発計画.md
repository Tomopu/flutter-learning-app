## LLM連携

以下の情報をまとめてLLMに渡し、教材文脈に沿った回答を生成する。

- 教材本文
- 学習目標
- 現在のコード
- 実行ログ
- エラーログ
- ユーザーの質問

教材生成では、個別教材を直接生成するのではなく、到達目標と成果物を定義し、そこへ到達するためのロードマップを細かいステップに分割してから、各ステップの教材下書きを生成する。

## 開発体制

開発人数は2人を想定する。

開発には以下のAI開発支援ツールを活用する。

- Claude Code
- Codex
- Antigravity

AIには、ドキュメント作成、Issue分割、実装補助、コードレビュー補助、教材生成補助を担わせる。

ただし、以下については人間が責任を持つ。

- プロダクト方針
- MVPスコープ
- アーキテクチャ判断
- 教材内容の正確性
- 公開判断
- セキュリティ判断

## 開発の進め方

MVPは2段階で実装する。

### 第一段階: ローカルDockerアプリケーション方式

フロントエンド、バックエンド、データベース、ビルド実行環境をローカルDocker上で起動し、ユーザーのローカル環境内でサーバービルドを実行する。

1. プロダクト概要を整理する
2. MVPスコープを定義する
3. 1つ目のFlutter教材を作成する
4. コードエディタを表示する
5. ファイルツリーと複数ファイル編集を実装する
6. ブラウザ上のコード保存を実装する
7. プロジェクト全体のダウンロード・アップロードを実装する
8. ファイル単位・プロジェクト単位の初期状態リセットを実装する
9. 模範解答タブを追加し、Markdown形式の模範解答を表示する
10. ローカルDocker上のFlutterビルド環境を用意する
11. ビルド要求ごとにワークスペースを生成する
12. ユーザーコードをプロジェクトファイル一式としてワークスペースに反映する
13. Flutter Webとしてサーバー側でビルドする
14. 実行結果をプレビュー表示する
15. ビルドログ・エラーログを表示する
16. LLM質問機能を追加する
17. 管理者向け画面を追加する
18. 教材の手動追加・編集機能を追加する
19. LLMロードマップ・教材下書き生成機能を追加する
20. 教材のdraft、published状態を管理する
21. GitHub IssueとProjectでタスク管理する

### 第二段階: クラウドサーバービルド方式

GCP、AWSなどのクラウド上にアプリケーションをデプロイし、ビルド要求ごとに一時的なワークスペースまたはコンテナを生成する。

1. クラウド上のアプリケーション構成を設計する
2. ビルドワーカーまたはワークスペース生成方式を設計する
3. ビルドキューを検討する
4. 成果物ストレージを用意する
5. 認証・認可を追加する
6. ビルド要求ごとにワークスペースを生成する
7. ビルドログと成果物をクラウド上で管理する
8. 監視、レート制限、コスト上限を検討する

## 備考

本プロダクトは、初期段階では個人利用を目的とした開発プロジェクトとする。

外部公開、商用展開、複数ユーザー利用を行う場合は、セキュリティ、利用規約、教材著作権、AI生成コンテンツの品質管理、実行環境の隔離、運用コストを改めて検討する。
