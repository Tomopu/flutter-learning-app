# 受け入れ基準

このドキュメントでは、MVPの各機能が完了したと判断するための条件を定義します。

## 1. 目的

要求、設計、実装、テストの判断基準を揃え、実装完了の定義を明確にします。

## 2. 共通基準

- 主要な操作が画面上で完了できる。
- 成功、失敗、読み込み中の状態がユーザーに分かる。
- 想定外の入力や失敗時に、画面が壊れずエラーを表示できる。
- 正式ドキュメントに記載された要求と矛盾しない。

## 3. 学習者向け機能

### 3.1 教材一覧

- 公開済み教材を一覧表示できる。
- 教材名、概要、難易度、言語ラベルを確認できる。
- 教材を選択して学習メイン画面へ遷移できる。

### 3.2 学習メイン画面

- 教材本文とコードエディタを同時に確認できる。
- ファイルツリーから編集対象ファイルを切り替えられる。
- コードの編集状態を保持できる。
- プロジェクト全体をダウンロード、アップロードできる。
- 初期状態へリセットできる。

### 3.3 ビルドとプレビュー

- ビルド要求を送信できる。
- ビルド中、成功、失敗の状態を確認できる。
- 成功時にプレビューを確認できる。
- 失敗時にログとエラー内容を確認できる。

### 3.4 模範解答

- 模範解答の表示前に確認を挟む。
- 模範解答をMarkdown形式で表示できる。
- 模範解答表示によって現在のコードが上書きされない。

### 3.5 LLM質問

- 学習者が質問を入力できる。
- 教材やコードに関する回答を表示できる。
- LLM応答失敗時にエラーを表示できる。

## 4. 管理者向け機能

### 4.1 教材管理

- 教材を作成、編集、削除できる。
- 教材本文、初期コード、模範解答を編集できる。
- 公開状態を管理できる。

### 4.2 一括操作

- 複数教材を選択できる。
- 一括公開状態変更、一括削除を実行できる。
- 実行前に確認を挟む。

### 4.3 LLM教材生成

- 到達目標や成果物からロードマップ案を生成できる。
- ロードマップから教材下書きを生成できる。
- 生成内容は管理者の確認なしに公開されない。
