# システムアーキテクチャ

## 1. 概要

本プロダクトは、フロントエンド・バックエンド・データベース・ビルド実行環境・LLMプロバイダーで構成するWebアプリケーションである。

MVPは2段階で実装する。

- **第一段階**: 全コンポーネントをローカルDocker上で動作させる
- **第二段階**: クラウド上にデプロイし、ビルド要求ごとに一時コンテナ・ワークスペースを生成する

## 3. MVP第一段階: ローカルDockerアプリケーション方式

### 3.1 Docker Compose構成

```
docker-compose.yml
├── frontend          Next.js
├── backend           Node.js + Hono
├── db                PostgreSQL
└── builder           Flutter SDK を含むビルド用コンテナ
```

ビルド要求ごとに、builderコンテナ内に一時ワークスペースを生成し、Flutter Webビルドを実行する。

### 3.2 ネットワーク構成

```
ブラウザ (ホストマシン)
  │ localhost:3000  ← ホストのポートマッピング経由
  ▼
frontend (Next.js コンテナ)
  │ http://backend:4000  ← Docker内部ネットワーク（サービス名で解決）
  ▼
backend (Hono コンテナ)
  ├── postgres:5432      → db (PostgreSQL コンテナ)
  └── http://builder:... → builder (Flutter SDK コンテナ)
```

コンテナ間通信はDocker Composeの内部ネットワークを通じてサービス名で解決する。ブラウザからフロントエンドへのアクセスのみ、ホスト側のポートマッピング（`localhost:3000`）を経由する。

ブラウザから直接builderへのアクセスは行わない。ビルド要求はbackend経由で制御する。

### 3.3 コード保存とビルドの流れ

```
ブラウザ (IndexedDB)
  │ 学習者がコードを編集→保存
  │
  │ POST /api/builds
  │  { lessonId, files: [{path, content}, ...], buildConfig }
  ▼
backend
  │ ビルド要求を Build レコードとして保存 (status: queued)
  │ ワークスペースを生成
  │ 教材の初期プロジェクト + 学習者のファイルを配置
  │ status: running
  ▼
builder (Flutter SDK コンテナ内ワークスペース)
  │ flutter pub get
  │ flutter build web
  │ stdout / stderr を BuildLog として保存
  ▼
backend
  │ status: succeeded / failed / timeout
  │ 成果物パスまたはエラー情報を返す
  │ ワークスペースを破棄
  ▼
ブラウザ
  GET /api/builds/:buildId        → 状態をポーリング or SSE で受信
  GET /api/builds/:buildId/logs   → コンソール表示
  GET /api/builds/:buildId/artifacts → プレビュー表示
```

## 4. MVP第二段階: クラウドサーバービルド方式

### 4.1 構成概要

```
ブラウザ
  │
  ▼
フロントエンド (CDN or コンテナ)
  │
  ▼
バックエンドAPI (コンテナ)
  ├── マネージドDB (PostgreSQL)
  ├── ビルドキュー (BullMQ / Cloud Tasks / SQS 等)
  └── ビルドワーカー
        └── ビルド要求ごとに一時コンテナ / ワークスペースを生成
              └── Flutter SDK でビルド実行
                    └── 成果物をオブジェクトストレージ (S3 / Cloud Storage) へ
```

### 4.2 第一段階からの主な変更点

| 項目 | 第一段階 | 第二段階 |
|------|---------|---------|
| デプロイ先 | ローカルDocker | GCP / AWS |
| ビルド環境 | builderコンテナ（固定） | 要求ごとに一時コンテナ生成 |
| ビルドキュー | なし（シンプルな上限制御） | BullMQ / Cloud Tasks 等 |
| 成果物保存 | ローカルボリューム | S3 / Cloud Storage |
| 認証・認可 | なし | 必須 |
| 監視 | なし | OpenTelemetry / Cloud Logging 等 |

## 5. 主要データフロー

### 5.1 学習者: 教材閲覧から学習開始まで

```
GET /api/lessons
  → published の Lesson 一覧を返す（LanguageLabel でフィルタ可）

GET /api/lessons/:lessonId
  → Lesson 詳細（本文・学習目標・レベル）を返す

GET /api/lessons/:lessonId/initial-project
  → 教材の初期プロジェクトファイル一式を返す
  → ブラウザの IndexedDB に保存してエディタに表示
```

### 5.2 学習者: ビルド実行

```
POST /api/builds
  → Build レコードを作成 (status: queued)
  → { buildId, status: "queued" } を即時返却

GET /api/builds/:buildId  (ポーリング or SSE)
  → status が succeeded / failed / timeout になるまで監視

GET /api/builds/:buildId/logs
  → BuildLog を返す（stdout / stderr / system）

GET /api/builds/:buildId/artifacts
  → ビルド成果物の参照先を返す → iframe でプレビュー表示
```

### 5.3 学習者: LLM質問

```
POST /api/llm/questions
  Body: {
    lessonId,
    question,
    context: {
      currentCode: { "lib/main.dart": "..." },
      buildLog: "...",
      errorLog: "..."
    }
  }
  → LlmQuestion レコードを保存
  → LLMプロバイダーAPIを呼び出し
  → { answer } を返す
```

### 5.4 管理者: LLM教材生成

```
POST /api/admin/llm/roadmaps
  Body: { goal, finalDeliverable, targetLevel, ... }
  → LlmGeneration レコードを作成 (status: pending, type: roadmap_generation)
  → { generationId } を返す（非同期）

GET /api/admin/llm/generations/:generationId
  → status が completed になるまでポーリング
  → output に生成されたロードマップが入る

  → 管理者が Roadmap / RoadmapStep を確認・編集
  → Lesson を作成し RoadmapStep に紐づける
  → 内容確認後に published へ変更
```

### 5.5 初期状態リセット（学習者）

```
学習者がリセット操作
  → GET /api/lessons/:lessonId/initial-project
  → ブラウザの IndexedDB を初期プロジェクトで上書き
  （ファイル単位リセットはフロントエンド側で IndexedDB を部分更新）
```

## 7. API構成

詳細は [API設計](../07_technology/03_API設計.md) を参照する。

| グループ | プレフィックス | 主な用途 |
|---------|-------------|---------|
| 学習者向け | `/api/lessons` | 教材一覧・詳細・初期プロジェクト取得 |
| ビルド | `/api/builds` | ビルド要求・状態・ログ・成果物 |
| LLM質問 | `/api/llm/questions` | 学習者のLLM質問 |
| 管理者向け教材 | `/api/admin/lessons` | 教材追加・編集・公開管理・一括操作 |
| 管理者向けロードマップ | `/api/admin/roadmaps` | ロードマップ・ステップ管理 |
| 管理者向けLLM | `/api/admin/llm/*` | ロードマップ・教材・修正案の生成 |
