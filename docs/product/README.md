## 現在の方針

- 最初の対象はFlutterに限定する
- ただし、設計は将来的な多言語・多フレームワーク対応を前提にする
- MVPではサーバービルド方式を採用する
- MVP第一段階はローカルDocker上で完結するアプリケーション方式とする
- MVP第二段階はクラウド上でワークスペースまたはコンテナを生成する方式とする
- 管理者向け画面をMVPから実装対象に含める
- Admin画面では教材の一括公開状態変更、一括削除、言語ラベル管理を扱う
- LLM教材生成は、到達目標と成果物からロードマップを作成してから、各ステップの教材を生成する
- LLM教材修正案生成はMVP対象とし、自動反映は行わない
