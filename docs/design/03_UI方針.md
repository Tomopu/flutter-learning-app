# UI方針

## コンセプト

開発ツール・IDEに近い操作感を持つ、ダークモード中心のUIを想定する。
学習者がコードとドキュメントに集中できるよう、装飾は最小限にする。

## カラー

| 用途 | 方針 |
|------|------|
| 背景 | ダークグレー系（例: `#1e1e1e` VSCode風） |
| パネル境界 | 薄いボーダーまたは濃淡差で区切る |
| アクセント | 1色に絞る（未定。Flutterブルー系が候補） |
| エラー表示 | 赤系 |
| 成功/完了 | 緑系 |

ライトモード対応は初期スコープ外。

## タイポグラフィ

| 用途 | フォント |
|------|--------|
| コードエディタ | 等幅フォント（JetBrains Mono / Fira Code 等） |
| 教材本文 | サンセリフ系（読みやすさ優先） |
| UI全般 | システムフォント or Noto Sans JP（日本語対応） |

## レイアウト原則

- 左右ペインの幅はリサイズ可能（ドラッグ操作）
- 上下パネルの高さもリサイズ可能
- 各ペインにはデフォルト幅・高さの比率を定める（例: 左30% / 右70%、上70% / 下30%）
- レスポンシブ対応は初期スコープ外（デスクトップ幅前提）

## コンポーネント方針

| コンポーネント | 選定方針 |
|--------------|---------|
| コードエディタ | Monaco Editor（VS Codeと同エンジン）を第一候補とする |
| Markdownレンダリング | react-markdown 等の標準的なライブラリを使用 |
| ファイルツリー | シンプルな実装で対応（複雑なDnDは不要） |
| ターミナル/コンソール | xterm.js またはシンプルな`<pre>`スクロール表示 |
| LLMチャット | 独自実装（バブル形式、スクロール、送信ボタン） |

## UIの優先順位

1. 機能が正しく動くこと（壊れていないこと）
2. 操作が直感的であること
3. 視覚的な洗練度

MVPでは3よりも1・2を優先する。デザインの統一やアニメーションは後回しでよい。
