## AI Summary

- 本プロダクトは、Flutter教材閲覧、コード編集、サーバービルド、プレビュー、ログ確認、LLM質問を統合したWeb学習環境である。
- MVP第一段階はローカルDocker上でfrontend、backend、db、builderを動かす。
- MVP第二段階はクラウド上でビルド要求ごとに一時ワークスペースまたはコンテナを生成する。
- MVPでは学習者向け画面とAdmin画面を実装する。
- LLM生成物は必ず `draft` として保存し、自動公開しない。
- コード提出、採点、ユーザー登録、課金、複数ユーザー運用はMVP対象外である。

## 1. はじめに

### 1.1 目的

この文書は、Flutter学習アプリのMVPで実現するソフトウェア要求を定義する。

本書はIEEE 830およびISO/IEC/IEEE 29148の考え方を参考に、プロダクトの範囲、利用者、制約、機能要求、非機能要求、対象外、将来拡張を整理する。

### 1.2 対象読者

- プロダクトオーナー
- 開発者
- UI/UX設計者
- API/DB/バックエンド/フロントエンド設計者
- AI開発支援ツール

### 1.3 適用範囲

本書は、Flutter学習アプリのMVPに適用する。

MVPは次の2段階で扱う。

| フェーズ | 内容 |
|----------|------|
| MVP第一段階 | ローカルDockerアプリケーション方式 |
| MVP第二段階 | クラウドサーバービルド方式 |

本書では、第一段階を優先実装対象とし、第二段階は拡張前提として要求を整理する。

### 1.4 用語

| 用語 | 意味 |
|------|------|
| 学習者 | 教材を閲覧し、コードを編集し、ビルド結果を確認するユーザー |
| 管理者 | 教材、ロードマップ、公開状態、LLM生成物を管理するユーザー |
| 教材 | 学習本文、初期プロジェクト、模範解答、メタ情報を含む学習単位 |
| 初期プロジェクト | 学習開始時にエディタへ読み込むプロジェクトファイル一式 |
| 模範解答 | 学習者が参照できる解答例。現在のコードを上書きしない |
| サーバービルド | バックエンド管理下の実行環境でFlutter Webビルドを実行する方式 |
| ビルドワークスペース | ビルド要求ごとに作成する一時作業領域 |
| LLM生成物 | LLMが生成したロードマップ、教材下書き、教材修正案 |

## 2. 全体説明

### 2.1 プロダクトの位置づけ

本プロダクトは、Flutterを実践的に学ぶためのWebベース学習プラットフォームである。

教材閲覧、コード編集、ビルド、プレビュー、ログ確認、LLM質問を1つの画面体験として統合する。

### 2.2 プロダクトの目的

Flutterを学ぶ開発者が、文法やWidgetの使い方だけでなく、実務に近い開発体験を通じて設計、実装、実行、デバッグ、質問、修正の流れを学べるようにする。

### 2.3 ユーザー分類

| ID | ユーザー | 説明 |
|----|----------|------|
| ACT-001 | 学習者 | 教材を選び、コードを編集し、ビルド結果やLLM回答を見ながら学習する |
| ACT-002 | 管理者 | 教材、ロードマップ、公開状態、LLM生成物を管理する |

MVPでは、開発者本人または限定利用者が学習者と管理者を兼ねることを許容する。

### 2.4 運用環境

| フェーズ | 運用環境 |
|----------|----------|
| MVP第一段階 | ローカルDocker上でfrontend、backend、db、builderを動作させる |
| MVP第二段階 | クラウド上でアプリケーションを公開し、ビルド要求ごとに一時ワークスペースまたはコンテナを生成する |

### 2.5 制約

- 初期対象はFlutterに限定する。
- Flutter Webビルドはサーバービルド方式で実行する。
- テンプレート文字列差し替え方式を主要方式にしない。
- MVPでは本格的なユーザー登録、ログイン、課金、複数ユーザー運用を扱わない。
- LLM生成物は自動公開しない。
- ビルド環境はアプリケーション本体、DB、秘密情報から分離する。

### 2.6 前提

- 学習者はブラウザ上でコードを編集する。
- MVPでは学習者の編集中コードをブラウザ上に保存する。
- 管理者はAdmin画面から教材を作成・編集する。
- LLMは学習者質問とAdmin向け教材生成の補助として使う。
- 将来的な多言語・多フレームワーク対応を妨げない設計にする。

## 3. 外部インターフェース要求

### 3.1 ユーザーインターフェース

| ID | 要求 |
|----|------|
| UI-001 | システムは、教材一覧画面を提供しなければならない。 |
| UI-002 | システムは、教材本文、コードエディタ、プレビュー、ログ、LLM質問、模範解答を扱う学習メイン画面を提供しなければならない。 |
| UI-003 | システムは、教材作成、編集、公開状態管理、LLM生成物確認を扱うAdmin画面を提供しなければならない。 |
| UI-004 | システムは、ビルド中、成功、失敗、タイムアウトを画面上で識別可能に表示しなければならない。 |
| UI-005 | システムは、破壊的操作の前に確認を表示しなければならない。 |

### 3.2 APIインターフェース

| ID | 要求 |
|----|------|

| API-002 | システムは、Admin向け教材管理APIを提供しなければならない。 |
| API-003 | システムは、ビルド要求、ビルド状態、ビルドログ、成果物参照を扱うAPIを提供しなければならない。 |
| API-004 | システムは、学習者向けLLM質問APIを提供しなければならない。 |
| API-005 | システムは、Admin向けLLM教材生成APIを提供しなければならない。 |

### 3.3 データインターフェース

| ID | 要求 |
|----|------|
| DATA-001 | システムは、教材、ロードマップ、言語ラベル、ビルド履歴、LLM生成履歴を管理できなければならない。 |
| DATA-002 | システムは、教材本文をMarkdownとして扱えること。 |
| DATA-003 | システムは、教材ごとの初期プロジェクトと模範解答を管理できなければならない。 |

### 3.4 外部サービスインターフェース

| ID | 要求 |
|----|------|

## 4. 機能要求

### 4.1 教材閲覧

| ID | 優先度 | 要求 |
|----|--------|------|
| FR-001 | Must | システムは、公開済み教材の一覧を表示できなければならない。 |
| FR-002 | Must | システムは、教材タイトル、概要、対象レベル、言語ラベルを表示できなければならない。 |
| FR-003 | Must | システムは、選択した教材の本文をMarkdownとして表示できなければならない。 |
| FR-004 | Must | システムは、教材ごとの学習目標を表示できなければならない。 |
| FR-005 | Should | システムは、教材一覧を言語ラベルで絞り込み、並び替えできることが望ましい。 |

### 4.2 コード編集

| ID | 優先度 | 要求 |
|----|--------|------|
| FR-101 | Must | システムは、ブラウザ上でコードを編集できるエディタを提供しなければならない。 |
| FR-102 | Must | システムは、教材に対応する複数ファイルを表示・編集できなければならない。 |
| FR-103 | Must | システムは、教材ごとの初期プロジェクトをエディタに読み込めなければならない。 |
| FR-104 | Must | システムは、編集中コードをブラウザ上に保存できなければならない。 |
| FR-105 | Must | システムは、画面リロード後も編集中コードを復元できなければならない。 |
| FR-106 | Should | システムは、現在のプロジェクト全体をローカルへダウンロードできることが望ましい。 |
| FR-107 | Should | システムは、ローカルからプロジェクトファイルをアップロードし、編集状態として復元できることが望ましい。 |
| FR-108 | Must | システムは、ファイル単位またはプロジェクト単位で初期状態へリセットできなければならない。 |

### 4.3 サーバービルドとプレビュー

| ID | 優先度 | 要求 |
|----|--------|------|
| FR-201 | Must | システムは、学習者の操作によりビルド要求を作成できなければならない。 |
| FR-202 | Must | システムは、ビルド要求ごとに一時ワークスペースを生成できなければならない。 |
| FR-203 | Must | システムは、初期プロジェクトと学習者の編集ファイルをワークスペースへ反映できなければならない。 |
| FR-204 | Must | システムは、ワークスペース上でFlutter Webビルドを実行できなければならない。 |
| FR-205 | Must | システムは、ビルド状態を `queued`、`running`、`succeeded`、`failed`、`timeout` のいずれかとして管理できなければならない。 |
| FR-206 | Must | システムは、ビルドログを学習者へ表示できなければならない。 |
| FR-207 | Must | システムは、ビルド成功時にFlutter Web成果物をプレビュー表示できなければならない。 |
| FR-208 | Must | システムは、ビルド失敗時にエラー内容を確認できるログを表示しなければならない。 |

### 4.4 模範解答

| ID | 優先度 | 要求 |
|----|--------|------|
| FR-301 | Must | システムは、教材ごとの模範解答をMarkdown形式で表示できなければならない。 |
| FR-302 | Must | システムは、模範解答表示によって現在の編集中コードを上書きしてはならない。 |
| FR-303 | Should | システムは、模範解答の初回表示時に確認を表示することが望ましい。 |

### 4.5 LLM質問

| ID | 優先度 | 要求 |
|----|--------|------|
| FR-401 | Must | システムは、学習者が教材やコードについてLLMへ質問できる入力欄を提供しなければならない。 |
| FR-402 | Must | システムは、教材本文、現在のコード、ビルドログ、エラーログ、質問内容を必要な範囲でLLM問い合わせに利用できなければならない。 |
| FR-403 | Must | システムは、LLMからの回答を学習画面に表示できなければならない。 |
| FR-404 | Must | システムは、LLM問い合わせ失敗時に失敗状態を表示できなければならない。 |
| FR-405 | Won't | MVPでは、LLM回答を自動でコードへ反映しない。 |

### 4.6 Admin教材管理

| ID | 優先度 | 要求 |
|----|--------|------|
| FR-501 | Must | システムは、Admin画面から教材を作成できなければならない。 |
| FR-502 | Must | システムは、Admin画面から既存教材を編集できなければならない。 |
| FR-503 | Must | システムは、教材本文、初期プロジェクト、模範解答、メタ情報を編集できなければならない。 |
| FR-504 | Must | システムは、教材の公開状態として `draft` と `published` を管理できなければならない。 |
| FR-505 | Must | システムは、`published` の教材だけを学習者向け一覧に表示しなければならない。 |
| FR-506 | Should | システムは、複数教材の公開状態変更または削除を一括実行できることが望ましい。 |
| FR-507 | Must | システムは、教材削除または一括操作の前に確認を表示しなければならない。 |

### 4.7 Admin向けLLM教材生成

| ID | 優先度 | 要求 |
|----|--------|------|
| FR-601 | Must | システムは、到達目標と成果物からロードマップ案を生成できなければならない。 |
| FR-602 | Must | システムは、ロードマップ上のステップから教材下書きを生成できなければならない。 |
| FR-603 | Should | システムは、既存教材に対する修正案をLLMで生成できることが望ましい。 |
| FR-604 | Must | システムは、LLM生成物を自動公開せず `draft` として保存しなければならない。 |
| FR-605 | Must | システムは、管理者がLLM生成物を確認・編集してから公開できなければならない。 |

## 5. 非機能要求

非機能要求の正本は [04_非機能要件.md](04_非機能要件.md) とする。

本SRSでは、特に重要な非機能要求だけを要約する。

| ID | 要約 |
|----|------|
| NFR-SEC-001 | ビルド環境はアプリケーション本体、DB、秘密情報から分離する。 |
| NFR-SEC-002 | LLMへ秘密情報、APIキー、DB接続情報、ホストパスを送らない。 |
| NFR-REL-001 | ビルド処理にはタイムアウトを設定する。 |
| NFR-REL-002 | ビルドワークスペースは完了、失敗、タイムアウト後に破棄する。 |
| NFR-PERF-001 | ビルド中は処理状態を画面に表示する。 |
| NFR-MAINT-001 | 教材、ビルド、LLM、Admin機能の責務を分離する。 |
| NFR-UX-001 | 学習者が読む、書く、実行する、確認する、質問する流れを同一画面上で行えるようにする。 |
