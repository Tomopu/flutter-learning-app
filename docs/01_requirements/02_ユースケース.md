## AI Summary

- 学習者の主要フローは、教材選択、コード編集、ビルド、プレビュー、ログ確認、LLM質問、模範解答確認である。
- 管理者の主要フローは、教材作成・編集、公開状態管理、LLMロードマップ生成、LLM教材生成である。
- MVPでは複数人承認やユーザー管理は扱わない。

## 1. 目的

この文書では、要求仕様を画面設計、API設計、受け入れ基準へ落とし込むために、ユーザー視点の主要シナリオを定義する。

## 2. アクター

| ID | アクター | 説明 |
|----|----------|------|
| ACT-001 | 学習者 | 教材を選択し、コードを編集し、実行結果やLLM回答を見ながら学習する |
| ACT-002 | 管理者 | 教材、ロードマップ、公開状態、LLM生成物を管理する |

## 3. 学習者ユースケース

### UC-001 教材を探して学習を開始する

| 項目 | 内容 |
|------|------|
| 主アクター | 学習者 |
| 関連要求 | FR-001, FR-002, FR-003, FR-004 |
| 事前条件 | 公開済み教材が存在する |
| 事後条件 | 学習メイン画面で教材と初期プロジェクトを確認できる |

基本フロー:

1. 学習者は教材一覧画面を開く。
2. システムは公開済み教材の一覧を表示する。
3. 学習者は教材を選択する。
4. システムは教材本文、学習目標、初期プロジェクトを表示する。

例外フロー:

- 公開済み教材が存在しない場合、システムは空状態を表示する。
- 教材取得に失敗した場合、システムはエラー状態を表示する。

### UC-002 コードを編集して保存する

| 項目 | 内容 |
|------|------|
| 主アクター | 学習者 |
| 関連要求 | FR-101, FR-102, FR-103, FR-104, FR-105 |
| 事前条件 | 学習メイン画面を開いている |
| 事後条件 | 編集内容がブラウザ上に保存される |

基本フロー:

1. 学習者はファイルツリーからファイルを選択する。
2. システムは選択ファイルをエディタに表示する。
3. 学習者はコードを編集する。
4. システムは編集内容をブラウザ上に保存する。
5. 学習者が画面を再読み込みしても、システムは編集内容を復元する。

### UC-003 ビルドしてプレビューを確認する

| 項目 | 内容 |
|------|------|
| 主アクター | 学習者 |
| 関連要求 | FR-201, FR-202, FR-203, FR-204, FR-205, FR-206, FR-207, FR-208 |
| 事前条件 | 編集対象プロジェクトが存在する |
| 事後条件 | ビルド結果、ログ、プレビューまたはエラーを確認できる |

基本フロー:

1. 学習者はビルドボタンを押す。
2. システムはビルド要求を作成する。
3. システムはワークスペースを生成する。
4. システムはFlutter Webビルドを実行する。
5. システムはビルド状態とログを表示する。
6. ビルド成功時、システムはプレビューを表示する。

例外フロー:

- ビルド失敗時、システムはエラーログを表示する。
- ビルドタイムアウト時、システムはタイムアウト状態を表示する。

### UC-004 LLMに質問する

| 項目 | 内容 |
|------|------|
| 主アクター | 学習者 |
| 関連要求 | FR-401, FR-402, FR-403, FR-404 |
| 事前条件 | 学習メイン画面を開いている |
| 事後条件 | LLM回答または失敗状態を確認できる |

基本フロー:

1. 学習者はLLMタブを開く。
2. 学習者は質問を入力する。
3. システムは教材、現在のコード、ログを必要な範囲でコンテキスト化する。
4. システムはLLMへ問い合わせる。
5. システムは回答を表示する。

例外フロー:

- LLM問い合わせに失敗した場合、システムは失敗状態を表示する。

### UC-005 模範解答を確認する

| 項目 | 内容 |
|------|------|
| 主アクター | 学習者 |
| 関連要求 | FR-301, FR-302, FR-303 |
| 事前条件 | 教材に模範解答が存在する |
| 事後条件 | 模範解答を確認でき、編集中コードは上書きされない |

基本フロー:

1. 学習者は模範解答タブを開く。
2. 初回表示時、システムは確認を表示する。
3. 学習者が確認すると、システムは模範解答をMarkdownで表示する。
4. システムは現在の編集中コードを変更しない。

## 4. 管理者ユースケース

### UC-101 教材を作成する

| 項目 | 内容 |
|------|------|
| 主アクター | 管理者 |
| 関連要求 | FR-501, FR-503, FR-504 |
| 事前条件 | Admin画面を開いている |
| 事後条件 | 教材が `draft` または `published` として保存される |

基本フロー:

1. 管理者は教材作成画面を開く。
2. 管理者は教材本文、初期プロジェクト、模範解答、メタ情報を入力する。
3. 管理者は下書き保存または公開を選択する。
4. システムは教材を保存する。

### UC-102 教材を編集・公開状態変更する

| 項目 | 内容 |
|------|------|
| 主アクター | 管理者 |
| 関連要求 | FR-502, FR-503, FR-504, FR-505, FR-507 |
| 事前条件 | 対象教材が存在する |
| 事後条件 | 教材内容または公開状態が更新される |

基本フロー:

1. 管理者は教材一覧から教材を選択する。
2. 管理者は教材本文、初期プロジェクト、模範解答、メタ情報を編集する。
3. 管理者は保存または公開状態変更を実行する。
4. システムは確認が必要な操作では確認を表示する。
5. システムは教材を更新する。

### UC-103 教材を一括操作する

| 項目 | 内容 |
|------|------|
| 主アクター | 管理者 |
| 関連要求 | FR-506, FR-507 |
| 事前条件 | 複数教材が存在する |
| 事後条件 | 選択教材の状態変更または削除が実行される |

基本フロー:

1. 管理者は教材一覧で複数教材を選択する。
2. 管理者は一括操作を選択する。
3. システムは確認を表示する。
4. 管理者が確認すると、システムは一括操作を実行する。

### UC-104 LLMでロードマップと教材下書きを生成する

| 項目 | 内容 |
|------|------|
| 主アクター | 管理者 |
| 関連要求 | FR-601, FR-602, FR-604, FR-605 |
| 事前条件 | 管理者が到達目標と成果物を入力できる |
| 事後条件 | LLM生成物が `draft` として保存され、管理者が確認できる |

基本フロー:

1. 管理者は到達目標、成果物、対象レベルを入力する。
2. システムはLLMでロードマップ案を生成する。
3. 管理者はロードマップ案を確認・編集する。
4. システムは各ステップの教材下書きを生成する。
5. システムは生成物を `draft` として保存する。
6. 管理者は生成物を確認・編集し、必要に応じて公開する。

## 5. 対象外ユースケース

- ユーザー登録する。
- 課金する。
- 複数管理者で承認する。
- コードを提出して採点を受ける。
- 学習進捗をサーバーに保存する。
