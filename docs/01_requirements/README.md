# requirements

このディレクトリでは、プロダクトが何を実現し、どの条件を満たすべきかを定義する要求仕様を管理します。

要求仕様は、設計や実装より上位の判断根拠です。画面、API、DB、バックエンドなどの設計は、このディレクトリの内容を満たすために作成します。

## ドキュメント

- [00_プロダクト概要.md](00_プロダクト概要.md): 背景、目的、提供価値、初期スコープ、将来方針
- [01_要求仕様書.md](01_要求仕様書.md): MVPおよび将来拡張に向けた主要な機能要件
- [02_ユースケース.md](02_ユースケース.md): 学習者・管理者の主要な利用シナリオ
- [03_受け入れ基準.md](03_受け入れ基準.md): 実装完了を判断するための条件
- [04_非機能要件.md](04_非機能要件.md): セキュリティ、信頼性、性能、保守性などの品質要求

## 役割

- `requirements` は「何を作るか」「何を満たすか」を扱う。
- 技術選定や内部構造などの「どう作るか」は [03_design/](../03_design/) に置く。
- 文書や開発のルールは [02_standards/](../02_standards/) に置く。
- 未整理の要求メモは [99_drafts/01_requirements/](../99_drafts/01_requirements/) に置き、採用が決まったものだけ正式文書へ反映する。
