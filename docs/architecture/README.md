# architecture

このディレクトリでは、プロダクト全体のアーキテクチャ方針を管理します。

技術ごとの詳細設計は [technology/](../technology/) に置き、このディレクトリではシステム全体の構成、境界づけられたコンテキスト、主要な責務分割を扱います。

## 現在あるドキュメント

- [システムアーキテクチャ](01_システムアーキテクチャ.md)

## アーキテクチャ方針の要点

- MVP第一段階では、フロントエンド、バックエンド、データベース、ビルド実行環境をローカルDocker上で動作させる
- MVP第二段階では、クラウド上でビルド要求ごとに一時ワークスペースまたはコンテナを生成する
- 教材管理、学習体験、ビルド実行、LLM連携の責務を分離する
- Lesson、Course、RoadmapなどのドメインモデルはFlutter専用にしすぎない
- 学習者コードはMVPではブラウザ上に保存し、プロジェクト全体のダウンロード・アップロードに対応する
- 模範解答は学習体験の一部として扱うが、コード提出と採点はMVPでは扱わない
- Admin機能はMVPから扱うが、外部公開時には認証・認可を必須にする
