# アーキテクチャ設計

## 1. ドメイン概要

教材閲覧・コード編集・サーバービルド・LLM質問を1つのWebアプリ上で統合した、実践型プログラミング学習プラットフォーム。

初期はFlutterに特化するが、ドメインモデルはFlutter専用にしない。将来的にJavaScript・TypeScript・Python・Goなど複数言語に拡張できることを前提として設計する。

---

## 2. ユーザー種別

| 種別 | 役割 |
|------|------|
| **学習者 (Learner)** | 教材を閲覧し、コードを編集・実行・質問する |
| **管理者 (Admin)** | 教材を追加・編集・公開管理する。LLMで教材下書きを生成する |

MVPでは開発者本人が両者を兼ねる。認証・認可はMVP外だが、APIレベルでの権限境界は分離する。

## 4. 各コンテキストのビジネス要件

### 4.1 教材管理コンテキスト

**目的:** 教材のライフサイクル全体を管理する。

**集約と主要エンティティ:**

| エンティティ | 役割 |
|------------|------|
| Course | 複数Lessonをまとめるグループ単位 |
| Lesson | 学習者が閲覧・実行する教材の単位 |
| Roadmap | 到達目標と成果物に向かうカリキュラムパス |
| RoadmapStep | Roadmapを構成する各ステップ。Lessonと紐づく |
| LanguageLabel | 教材に付与するプログラミング言語/フレームワーク名 |

**公開状態 (Status):**
- `draft`: 下書き。学習者には表示しない
- `published`: 公開中。学習者に表示する
- （将来）`review`: 複数人レビュー段階で追加

**主要ビジネスルール:**
- LessonはCourseなしでも作成できる（courseIdはNULL許容）
- CourseとRoadmapは独立した概念。1つのLessonが複数のRoadmapに属してよい
- RoadmapStep生成直後はlessonIdがNULLのことがある。後から紐づける運用
- LLMが生成したLessonとRoadmapは必ず`draft`として保存し、自動公開しない
- 管理者が内容・コード・依存関係・著作権・誤情報を確認してから`published`に変更する

**Lessonの主要属性:**
- タイトル、概要、対象レベル（beginner / intermediate / advanced）
- 教材本文（Markdown）
- 学習目標
- 初期プロジェクト参照（initialProjectRef）
- 参考プロジェクト参照（solutionProjectRef）
- 言語ラベル（複数付与可）
- 公開状態

---

### 4.2 学習体験コンテキスト

**目的:** 学習者がコードを読む・書く・実行する・質問するという一連の体験を提供する。

**主な責務:**
- 教材本文（Markdown）の表示
- コードエディタ（Monaco Editor）の提供
- ファイルツリーによる複数ファイル編集
- コードのブラウザ保存（IndexedDB）
- プロジェクト全体のダウンロード・アップロード（ZIP形式）
- ファイル単位またはプロジェクト単位の初期状態リセット

**主要ビジネスルール:**
- コードはブラウザのIndexedDBに保存する。軽量なUI状態のみLocalStorageを使う
- 初期状態リセットは破壊的操作のため、実行前に確認を表示する
- アップロード時はパス・ファイルサイズ・ファイル数・プロジェクト構成を検証する（上限目安: 1ファイル1MB、合計50MB、500ファイル）
- 危険なパス（`..`を含む、絶対パス等）はアップロードを拒否する
- 編集範囲はビルド用ワークスペース内のプロジェクトファイルに閉じる

---

### 4.3 ビルド実行コンテキスト

**目的:** 学習者のコードをサーバー側の隔離環境でビルドし、結果を返す。

**集約と主要エンティティ:**

| エンティティ | 役割 |
|------------|------|
| Build | ビルド要求と結果を表す集約ルート |
| BuildLog | ビルド時のstdout / stderr / systemログ |
| Workspace | ビルド要求ごとに生成される一時的な隔離環境（DB上のエンティティではない） |

**Buildのステータス遷移:**
```
queued → running → succeeded
                 → failed
                 → timeout
                 → cancelled
```

**ビルド要求の主要情報:**
- 教材ID（lessonId）
- プロジェクトファイル一式
- ビルド設定（target: web等）

**主要ビジネスルール:**
- ビルドは隔離されたワークスペース上で実行する
- ワークスペースはアプリ本体・DB・秘密情報・ホストファイルにアクセスできない
- ビルド完了後にワークスペースを破棄する
- ビルドにはタイムアウトを設ける（30〜120秒目安）
- 同時ビルド数に上限を設ける（MVP第一段階: 1〜2件目安）
- ビルド要求とビルド実行処理は責務を分離し、将来のキュー化を妨げない

---

### 4.4 LLM連携コンテキスト

**目的:** 学習者向け質問応答と管理者向け教材生成・修正案生成を扱う。

**集約と主要エンティティ:**

| エンティティ | 役割 |
|------------|------|
| LlmGeneration | ロードマップ生成・教材生成・教材修正案生成の履歴 |
| LlmQuestion | 学習者の質問と回答の履歴 |

**LlmGenerationのtype:**
- `roadmap_generation`: ロードマップ生成
- `lesson_generation`: 教材生成
- `lesson_revision`: 教材修正案生成

**LlmGenerationのステータス:**
- `pending`: 処理中
- `completed`: 正常完了
- `failed`: エラー終了

**LLMへ渡すコンテキスト（学習者質問）:**
- 教材本文
- 学習目標
- 現在のコード
- ビルドログ
- エラーログ
- ユーザーの質問

**LLM教材生成のフロー:**
1. 到達目標と最終成果物を定義する
2. 成果物に到達するロードマップをステップに分割する
3. 各ステップに対応する教材下書きを生成する

**主要ビジネスルール:**
- LLM生成物は必ず`draft`として保存し、自動公開しない
- 秘密情報・APIキー・DB接続情報・ホストパスをLLMに送らない
- LLM教材修正案の自動反映はしない。管理者が確認して手動反映する
- 特定のLLMプロバイダーに強く依存しないよう、バックエンドにLLMクライアント層を設ける

## 5. ユビキタス言語

| 用語 | 説明 |
|------|------|
| Learner（学習者） | 教材を閲覧・実行する利用者 |
| Admin（管理者） | 教材を管理・公開する利用者 |
| Course（コース） | 複数のLessonをまとめる単位 |
| Lesson（教材） | 学習者が閲覧・実行する1つの教材 |
| Roadmap（ロードマップ） | 到達目標と成果物に向かう学習カリキュラム |
| RoadmapStep（ロードマップステップ） | Roadmapを構成する各ステップ |
| LanguageLabel（言語ラベル） | 教材に付与するプログラミング言語/フレームワーク名 |
| Build（ビルド） | コードのビルド要求と実行結果 |
| BuildLog（ビルドログ） | ビルド時のログ（stdout/stderr/system） |
| Workspace（ワークスペース） | ビルド要求ごとに生成される一時的な隔離実行環境 |
| LlmGeneration（LLM生成） | ロードマップ・教材・修正案のLLM生成履歴 |
| LlmQuestion（LLM質問） | 学習者のLLM質問と回答の履歴 |
| initialProject（初期プロジェクト） | 教材が定義する学習開始時のプロジェクト状態 |
| solutionProject（参考プロジェクト） | 教材の模範解答または参考となるプロジェクト状態 |
| draft | 下書き状態。学習者に非公開 |
| published | 公開状態。学習者に表示 |
| ServerBuild（サーバービルド） | サーバー側の隔離環境でFlutter SDKを使ってビルドする方式 |

## 6. 主要な制約と方針

| 制約 | 内容 |
|------|------|
| 多言語対応前提 | Lesson/Course/RoadmapモデルはFlutter専用にしない |
| LLM生成はdraft必須 | 自動公開しない。管理者が確認後に公開する |
| ビルド隔離 | ワークスペースはアプリ本体・DB・秘密情報から分離する |
| コードはブラウザ保存 | IndexedDBに保存。サーバー側DBには保存しない（MVP） |
| 管理者API分離 | 学習者APIと管理者APIは権限境界を分ける |
| 秘密情報保護 | APIキー等をLLMやビルド環境に渡さない |

---

## 7. MVPスコープ外

- ユーザー登録・ログイン・認証認可
- 課金・教材販売
- 複数ユーザー・複数管理者の権限管理
- 本格的な承認ワークフロー（review状態）
- コード提出・採点・進捗管理
- GitHub連携
- モバイル対応
