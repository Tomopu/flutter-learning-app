# LLM連携設計

## 1. 目的

学習者向け質問、Admin向けロードマップ生成、教材生成、教材修正案生成におけるLLM連携の設計を定義する。

## 2. 基本方針

- LLM出力は信頼しない。
- LLM生成物は自動公開しない。
- 秘密情報、APIキー、DB接続情報、ホストパスはLLMへ送らない。
- LLM出力は構造検証してから保存する。
- プロンプトは用途ごとに分離する。

## 3. 利用ケース

| 用途 | 入力 | 出力 |
|------|------|------|
| 学習者質問 | 教材、現在のコード、ビルドログ、質問 | 回答 |
| ロードマップ生成 | 到達目標、成果物、対象レベル | Roadmap案 |
| 教材生成 | RoadmapStep、学習目標、制約 | Lesson下書き |
| 教材修正案生成 | 既存教材、問題点、修正方針 | 修正案 |

## 4. コンテキスト制御

学習者質問では、必要最小限の情報を送る。

- 教材ID、教材タイトル
- 教材本文の該当部分
- アクティブファイルの内容
- 必要な範囲の関連ファイル
- ビルドログまたはエラーログ
- 学習者の質問

送らない情報:

- APIキー
- DB接続情報
- ホスト上の絶対パス
- 他ユーザーの情報
- 管理者向け内部メモ

## 5. 出力検証

- JSON出力が必要な用途ではスキーマで検証する。
- 必須フィールドが欠けている場合は保存しない。
- Markdown本文は表示前にサニタイズする。
- コードブロックは教材の対象言語やファイル構成と照合する。

## 6. 保存

- LLM生成履歴は `LlmGeneration` として保存する。
- 学習者質問は必要に応じて `LlmQuestion` として保存する。
- Admin向け生成物は `draft` として扱う。
