## AI Summary

Flutter Webビルドをbuilderコンテナの隔離ワークスペースで実行し、完了・失敗・タイムアウト時にワークスペースを破棄する。ファイルパスはpath traversal検証必須、同時ビルド数はMVP第一段階で1〜2件を上限とする。ログは学習者向け（stdout/stderr）と内部向けを分離する。

## 1. 目的

学習者が編集したFlutterプロジェクトを、サーバー側で安全にFlutter Webビルドするための実行環境を定義する。

## 2. ビルド処理

```text
POST /api/builds
  -> 入力ファイル検証
  -> Buildレコード作成
  -> ワークスペース作成
  -> 初期プロジェクトを配置
  -> 学習者ファイルで上書き
  -> flutter pub get
  -> flutter build web
  -> ログ保存
  -> 成果物参照先を保存
  -> ワークスペース破棄
```

## 4. ワークスペース

- ビルド要求ごとに一意の作業ディレクトリを作成する。
- パス traversal を拒否する。
- 許可されたプロジェクトファイルだけを書き込む。
- ビルド完了、失敗、タイムアウト時に破棄する。

## 5. ログ

- stdout、stderr、systemログを分けて保存する。
- 学習者にはビルド理解に必要なログを表示する。
- 内部パスや秘密情報がログに混入しないようにする。

## 6. 成果物

- Flutter Webの成果物をプレビュー用に参照できる形で保存する。
- MVP第一段階ではローカルボリュームまたは一時ディレクトリを使用する。
- 第二段階ではオブジェクトストレージを使用する。

## 7. 制限

- ビルドタイムアウトを設定する。
- 同時ビルド数に上限を設定する。
- MVPでは同時1〜2ビルドを目安にする。
- 依存パッケージ取得の扱いはセキュリティと利便性のバランスを見て調整する。
