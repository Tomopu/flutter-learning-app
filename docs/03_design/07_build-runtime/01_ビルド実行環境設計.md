# ビルド実行環境設計

## 1. 目的

学習者が編集したFlutterプロジェクトを、サーバー側で安全にFlutter Webビルドするための実行環境を定義する。

## 2. 前提

- MVP第一段階ではローカルDocker上のbuilderコンテナで実行する。
- MVP第二段階ではクラウド上の一時ワークスペースまたは一時コンテナで実行する。
- ビルド要求はバックエンドAPIからのみ受け付ける。
- ビルド環境はDB、アプリケーション本体、秘密情報へ直接アクセスしない。

## 3. ビルド処理

```text
POST /api/builds
  -> 入力ファイル検証
  -> Buildレコード作成
  -> ワークスペース作成
  -> 初期プロジェクトを配置
  -> 学習者ファイルで上書き
  -> flutter pub get
  -> flutter build web
  -> ログ保存
  -> 成果物参照先を保存
  -> ワークスペース破棄
```

## 4. ワークスペース

- ビルド要求ごとに一意の作業ディレクトリを作成する。
- パス traversal を拒否する。
- 許可されたプロジェクトファイルだけを書き込む。
- ビルド完了、失敗、タイムアウト時に破棄する。

## 5. ログ

- stdout、stderr、systemログを分けて保存する。
- 学習者にはビルド理解に必要なログを表示する。
- 内部パスや秘密情報がログに混入しないようにする。

## 6. 成果物

- Flutter Webの成果物をプレビュー用に参照できる形で保存する。
- MVP第一段階ではローカルボリュームまたは一時ディレクトリを使用する。
- 第二段階ではオブジェクトストレージを使用する。

## 7. 制限

- ビルドタイムアウトを設定する。
- 同時ビルド数に上限を設定する。
- MVPでは同時1〜2ビルドを目安にする。
- 依存パッケージ取得の扱いはセキュリティと利便性のバランスを見て調整する。
