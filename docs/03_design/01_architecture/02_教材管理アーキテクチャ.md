# 教材管理アーキテクチャ

## 1. 目的

教材、ロードマップ、教材ステップ、初期プロジェクト、模範解答、LLM生成物、公開状態の関係を整理する。

この文書は、教材管理全体の構造と責務分割を扱う。DBの詳細は [DB設計](../04_data/01_DB設計.md)、Admin APIの詳細は [API設計](../03_api/01_API設計.md)、画面の詳細は [画面設計](../02_ui/02_画面設計.md) を参照する。

## 2. 基本方針

- 学習者に表示する教材は `published` のみとする。
- Adminは `draft` と `published` の両方を扱う。
- LLMが生成した教材、ロードマップ、修正案は自動公開しない。
- 教材本文、初期コード、模範解答、メタ情報は一体として管理する。
- 将来的な多言語・多フレームワーク対応を前提に、LessonをFlutter専用にしすぎない。

## 3. 概念モデル

```text
Roadmap
  └─ RoadmapStep
       └─ Lesson
            ├─ LessonBody
            ├─ InitialProject
            ├─ ModelAnswer
            ├─ LanguageLabel
            └─ PublicationStatus

LlmGeneration
  ├─ roadmap_generation
  ├─ lesson_generation
  └─ lesson_revision
```

## 4. 責務分割

| 領域 | 責務 |
|------|------|
| Admin UI | 教材作成、編集、公開状態変更、LLM生成結果の確認 |
| Backend | 教材管理API、公開状態制御、LLM生成履歴管理 |
| DB | 教材、ロードマップ、言語ラベル、生成履歴の永続化 |
| LLM連携 | ロードマップ案、教材下書き、修正案の生成 |

## 5. 公開状態

| 状態 | 意味 |
|------|------|
| `draft` | 管理者確認前または編集中 |
| `published` | 学習者に公開中 |
| `archived` | 将来的な非公開・履歴保持用 |

MVPでは `draft` と `published` を中心に扱う。`archived` は将来拡張として検討する。
