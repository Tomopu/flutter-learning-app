# 実行環境アーキテクチャ

## 1. 目的

Flutter Webビルドを安全に実行するための、ローカルDocker方式とクラウドサーバービルド方式の全体構成を整理する。

ビルド処理の詳細は [ビルド実行環境設計](../07_build-runtime/01_ビルド実行環境設計.md)、バックエンド内部処理は [バックエンド設計](../05_backend/01_バックエンド設計.md)、セキュリティ方針は [セキュリティ方針](../../02_standards/03_セキュリティ方針.md) を参照する。

## 2. 基本方針

- ブラウザからビルド実行環境へ直接アクセスしない。
- ビルド要求は必ずバックエンドAPIを経由する。
- ビルド環境はアプリケーション本体、DB、秘密情報から分離する。
- ビルド要求ごとにワークスペースを生成し、完了後に破棄する。
- MVP第一段階はローカルDocker、第二段階はクラウド上の一時ワークスペースまたはコンテナを想定する。

## 3. 第一段階: ローカルDocker方式

```text
browser
  -> frontend
  -> backend
  -> builder container
       -> temporary workspace
       -> flutter build web
```

第一段階では、Docker Compose上にfrontend、backend、db、builderを配置する。

## 4. 第二段階: クラウドサーバービルド方式

```text
browser
  -> frontend
  -> backend
  -> build queue
  -> build worker
       -> temporary container / workspace
       -> object storage
```

第二段階では、ビルドキュー、ワーカー、オブジェクトストレージ、監視、認証・認可を導入する。

## 5. 境界

| 境界 | 方針 |
|------|------|
| Browser -> Backend | API経由でビルド要求を送信 |
| Backend -> Builder | 検証済みファイルだけを渡す |
| Builder -> DB | 直接接続しない |
| Builder -> Host | 任意パスへアクセスしない |
| Builder -> Internet | MVPでは原則制限し、必要な依存解決だけを検討 |
