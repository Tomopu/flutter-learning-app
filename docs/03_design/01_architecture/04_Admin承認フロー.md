# Admin承認フロー

## 1. 目的

教材やLLM生成物を、下書きから公開状態へ変更するまでの承認フローを整理する。

この文書では、画面・API・データをまたぐ業務フローを扱う。画面詳細は [画面設計](../02_ui/02_画面設計.md)、API詳細は [API設計](../03_api/01_API設計.md)、データ状態は [DB設計](../04_data/01_DB設計.md) を参照する。

## 2. 基本方針

- LLM生成物は自動公開しない。
- 公開操作はAdminの明示的な操作で行う。
- 削除や一括公開などの影響が大きい操作は確認を挟む。
- MVPでは本格的な多段階承認は扱わない。
- 将来、外部公開する場合はAdmin認証・認可と操作ログを必須にする。

## 3. 教材作成フロー

```text
Adminが教材を作成
  -> draft保存
  -> プレビュー確認
  -> 承認して公開
  -> publishedとして学習者に表示
```

## 4. LLM教材生成フロー

```text
Adminが到達目標・成果物を入力
  -> LLMがロードマップ案を生成
  -> Adminが確認・編集
  -> LLMが教材下書きを生成
  -> Adminが本文・初期コード・模範解答を確認
  -> draft保存
  -> 承認して公開
```

## 5. 修正フロー

```text
published教材を編集
  -> draftとして保存
  -> 内容確認
  -> 再承認
  -> publishedへ反映
```

MVPでは、公開中教材の厳密なバージョン管理は扱わない。必要になった時点で、公開版と編集版を分離する方式を検討する。

## 6. 今後整理する項目

- 複数人承認
- 差し戻し理由
- 操作ログ
- 公開予約
- 公開済み教材のバージョン管理
