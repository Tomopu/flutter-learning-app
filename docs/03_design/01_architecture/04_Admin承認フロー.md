## AI Summary

教材をdraft→publishedへ変更するための承認フロー。LLM生成・手動作成を問わず必ずdraftから始まり、Adminの明示操作でのみ公開される。MVPでは多段階承認・操作ログ・バージョン管理は対象外。

## 基本方針

- LLM生成物は自動公開しない。
- 公開操作はAdminの明示的な操作で行う。
- 削除や一括公開などの影響が大きい操作は確認を挟む。
- MVPでは本格的な多段階承認は扱わない。
- 将来、外部公開する場合はAdmin認証・認可と操作ログを必須にする。

## 教材作成フロー

```text
Adminが教材を作成
  -> draft保存
  -> プレビュー確認
  -> 承認して公開
  -> publishedとして学習者に表示
```

## LLM教材生成フロー

```text
Adminが到達目標・成果物を入力
  -> LLMがロードマップ案を生成
  -> Adminが確認・編集
  -> LLMが教材下書きを生成
  -> Adminが本文・初期コード・模範解答を確認
  -> draft保存
  -> 承認して公開
```

## 修正フロー

```text
published教材を編集
  -> draftとして保存
  -> 内容確認
  -> 再承認
  -> publishedへ反映
```

MVPでは、公開中教材の厳密なバージョン管理は扱わない。必要になった時点で、公開版と編集版を分離する方式を検討する。
