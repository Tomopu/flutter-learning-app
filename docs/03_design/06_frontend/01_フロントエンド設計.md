# フロントエンド設計

## 1. 目的

Next.jsフロントエンドの内部構造、状態管理、API連携、コード保存、ビルド結果表示の方針を定義する。

画面レイアウトとUI表現は [画面設計](../02_ui/02_画面設計.md) と [UI方針](../02_ui/03_UI方針.md) を参照する。

## 2. 前提

- Next.js + TypeScriptを使用する。
- コードエディタにはMonaco Editorを使用する。
- 学習者の編集中コードはMVPではブラウザのIndexedDBに保存する。
- API通信はバックエンドAPIを経由する。
- ビルド結果のプレビューはバックエンドが返す成果物参照先をiframeなどで表示する。

## 3. 責務

- 教材一覧と教材詳細の表示
- 学習メイン画面のペイン、タブ、エディタ、プレビュー、コンソール表示
- Admin画面の教材管理UI
- IndexedDBへのコード保存
- プロジェクトファイルのダウンロード・アップロード
- ビルド要求、状態監視、ログ表示
- LLM質問と回答表示

## 4. 状態管理

| 状態 | 保存先 | 備考 |
|------|--------|------|
| 教材一覧 | メモリ / キャッシュ | APIから取得 |
| 教材詳細 | メモリ / キャッシュ | 画面遷移時に取得 |
| 編集中ファイル | IndexedDB | Lesson単位で保存 |
| アクティブファイル | UI状態 | 画面内状態 |
| ビルド状態 | API取得結果 | ポーリングまたはSSEを検討 |
| LLMチャット履歴 | MVPでは画面状態 | 永続化は将来検討 |

## 5. IndexedDB保存方針

- Lesson IDをキーに、プロジェクトファイル一式を保存する。
- 初回表示時は初期プロジェクトを取得して保存する。
- ファイル単位リセットでは対象ファイルだけを初期状態へ戻す。
- プロジェクト単位リセットではLessonの保存状態を初期プロジェクトで上書きする。

## 6. API連携

- 教材取得、ビルド、LLM質問、Admin操作はすべてAPI経由で行う。
- APIエラーはユーザーが理解できる形で表示する。
- ビルド中は重複実行を防ぐ。
- Adminの破壊的操作は確認ダイアログを挟む。
